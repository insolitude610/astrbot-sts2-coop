### 2.2 ❌ 「文档里 4 个环境变量是错的」

## 3. 正确启动方式（照抄即可）

### 3.1 主机（人类窗口）

```powershell
$g = "D:\SteamLibrary\steamapps\common\Slay the Spire 2"
Start-Process "$g\SlayTheSpire2.exe" -ArgumentList '-fastmp','host_standard' -WorkingDirectory $g
```

- `-fastmp host_standard` 让主机走**本地 ENet 33771**，玩家 NetId = **1**
- API 在 `127.0.0.1:8081`

> ⚠️ **验证参数是否生效的方法**：看 `/state` 的 `multiplayer.local_player_id`。
> 带 `-fastmp` → `"1"`；不带 → Steam ID（如 `76561199...`）。这是最可靠的判据。

### 3.2 队友实例（**7 个环境变量一个都不能少**）

```powershell
$g = "D:\SteamLibrary\steamapps\common\Slay the Spire 2"

$env:STS2_MULTIPLAYER_HOST_IP   = '127.0.0.1'
$env:STS2_MULTIPLAYER_NET_ID    = '2'          # 必须等于 --clientId
$env:STS2_API_PORT              = '8082'       # 不设会抢 8081 导致 mod 初始化失败
$env:STS2_API_ALLOW_FALLBACK    = '1'
$env:STS2_AGENT_ROLE            = 'companion'  # 决定 instance_role
$env:STS2_AGENT_AUTOPLAY        = '0'          # 0 = 外部接管，绝不让它自己调模型
$env:STS2_AGENT_SETTINGS_PATH   = "$env:APPDATA\STS2AIAgent\settings.companion.json"

Start-Process "$g\SlayTheSpire2.exe" `
  -ArgumentList '--windowed','--force-steam','off','--clientId','2','-fastmp','join' `
  -WorkingDirectory $g
```

**关键点**：

| 要项 | 漏了会怎样 |
|---|---|
| `STS2_API_PORT=8082` | 两个实例都抢 8081 → `HttpListenerException (183)` → **mod 初始化失败、整个 mod 不加载** |
| `STS2_AGENT_ROLE=companion` | `instance_role` 变成 `human`，只是"第二个单人实例"，不会加入房间 |
| `--force-steam off` | 需要 Steam 在线身份；加上则离线身份、Steam 不可见、不需要第二账号 |
| `--clientId 2` | 必须 = 主机 NetId + 1 |
| `-fastmp join` | 不会自动加入主机房间 |
| `--windowed` | 全屏，不方便观察 |

### 3.3 验证两侧都 OK

```powershell

# 队友：role=companion,       local_player_id=2, net_game_type=Client
curl http://127.0.0.1:8081/health
curl http://127.0.0.1:8082/health
```

两个都该看到 `connected_player_ids: ["1","2"]`、`player_count: 2`。

## 4. 新增功能：`sts2_autopilot`（模型自主接手）

### 4.1 起因

用户原话：

> 「我希望的效果是，这个 bot 和我在对话的时候，我提到了我们要去打牌了，
>  她能自己调用工具看到情况，然后接着继续开打」

查出真实缺口：**模型能看懂意图，但没有"接力棒"**。

| 层次 | 原来 | 现在 |
|---|---|---|
| 聊天时知道战况 | ✅ `inject_game_context` | 不变 |
| 自主调工具看局面/出牌 | ✅ `sts2_state` / `sts2_action` | 不变 |
| **看懂"你接手吧"并开始长局** | ❌ 只有 8 个关键词子串 | ✅ **新增 `sts2_autopilot`** |

原来的 `maybe_start_from_chat` 是纯关键词匹配，「继续和我一起打」不含任何触发词 → 不会触发。
而模型虽然能自主调 `sts2_action` 一步步打，但**每步都要一次 LLM 请求**（`max_steps: 60`），不可能打完一整局。

### 4.2 实现（`main.py` 末尾）

**1. 新增 LLM 工具**

```python
@filter.llm_tool(name="sts2_autopilot")
async def tool_sts2_autopilot(self, event, reason: str = "") -> str:
    """接手后台托管：从现在起由你一直替玩家打下去…"""
```

工具描述里**直接告诉模型什么时候该调**（说法随意，不用背固定词）：
「你来打吧」「帮我打」「继续和我一起打」「这局交给你了」「接着打」……

**2. 在 `inject_game_context` 里注入 `<sts2_hint>`**

模型不会凭空知道有个新工具，所以每轮注入时**额外**告诉它：

```
<sts2_hint>
如果玩家这句话的意思是「让你接手继续打」（说法随意，比如"你来打吧""帮我打"
"继续和我一起打""这局交给你""接着打""现在该怎么办你上"），
先调用 sts2_autopilot 接手后台托管，再简短回应一句。
如果玩家只是在聊天、问战况或讨论构筑，就不要调它。
</sts2_hint>
```

**3. 成本控制**：托管**已经在跑时不再注入 hint**，省 token。

**4. 安全边界**（与原有设计一致）：

| 检查 | 行为 |
|---|---|
| `operator_ids` 权限 | 非授权用户 → 「当前用户没有操作游戏的权限」 |
| 只在私聊（用 `event.is_private_chat()`） | 群聊 → 「只在私聊里自动接手托管；群里请用 /sts2 托管」 |
| `autopilot_from_chat` 开关 | 关掉 → 拒绝 |
| 已在下跑 | 返回提示，**不重复启动**（task 不被替换） |
| 游戏连不上 | 返回人话提示，不抛异常 |

> 注意：`MessageType` 不能从 `astrbot.api.event` 导入，用 `event.is_private_chat()` 更稳。

新增 `_project/harness/llm_autopilot_check.py`，**18/18 通过**：

## 5. 新发现：`snapshot_stabilizing`

这是今天最重要的技术发现，直接解释了 11-18 文档 D2「瞬时过期快照」的**具体机制**。

`/state` 里有个 `agent_view.combat.action_readiness` 结构：

```json
{
  "can_use_combat_actions": false,
  "reason": "snapshot_stabilizing",     // ← 等待快照稳定的明确原因
  "actions_settled": true,
  "snapshot_stable": false,
  "local_turn_ready": true,
  "player_action_phase": true,
  "local_ready_to_end_turn": false,
  "all_players_ready_to_end_turn": false,
  "combat_in_progress": true,
  "combat_room_mode": "ActiveCombat"
}
```

**这是联机同步的正常中间态，不是错误。** 实测 2~4 秒内自动变成：

```json
{ "can_use_combat_actions": true, "reason": "ready", "snapshot_stable": true }
```

其他 `reason` 值：

| reason | 含义 |
|---|---|
| `ready` | 可行动 |
| `snapshot_stabilizing` | 快照稳定中，等 2~4 秒 |
| `player_actions_disabled` | 已 end_turn，等队友 |

### 5.1 可选的改进方向（待评估）

现在插件靠**异常重试**处理这种情况（D2 的修法）。如果改成**读 `action_readiness.reason` 主动判断**，会更准确：

```python
ar = state.get("agent_view", {}).get("combat", {}).get("action_readiness", {})
if ar.get("can_use_combat_actions") is False:
    return {"action": "wait"}   # 而不是发出去再收 409
```

能避免无谓的 409 往返。**但现在的重试策略实测也能工作**，不急。

## 6. 环境坑：模型通道返回空 content

### 6.1 现象

22:55、22:58、22:59 三次，bot **不回复 QQ 私聊**，日志：

```
OpenAI completion has no usable output: finish_reason='stop' 但 message 内容为空
Switched from codex-for/gemini-3.8-flash to fallback chat provider: aihubmix/gemini-3.8-flash
...
502 - {'error': {'message': 'All available accounts exhausted'}}
```

耗时 38 秒后彻底失败。

### 6.2 排查结论

**不是插件问题，也不是"等打牌"。** 关键事实：

1. **出牌走规则层，根本不调模型** —— 所以游戏照打，只有聊天回复受影响
2. 「等打完当前动作再回」机制是**先暂停出牌**，不是等出牌 → 不可能卡住回复
3. 真因：模型通道返回 `finish_reason=stop` 但 content 为空（模型把内容全放进 reasoning），
   AstrBot 判定不可用 → 切 fallback → fallback 又 502 额度耗尽

**空 content 有两种，要分清**：

| 情况 | `finish_reason` | 正常？ |
|---|---|---|
| 只调工具、不回复文字 | `tool_calls` | ✅ 正常 |
| 输出全在 reasoning 里 | `stop` | ⚠️ **异常**（就是这个坑） |

### 6.3 处理：主模型换成 commandcode deepseek

对比测试（`compare_providers.py`）：

| 通道 | 成功 | 平均耗时 |
|---|---|---|
| `codex-for/gemini-3.8-flash` | **0/4** | 80.1s（2 次超时、2 次 400） |
| `commandcode/deepseek-v4.1-flash` | **4/4** | 20.1s |

**已改** `data\cmd_config.json` 的 `agent_runner.config.model`：

```json
{
  "provider_id": "commandcode/deepseek/deepseek-v4.1-flash",
  "fallback_provider_ids": [
    "deepseek_default_source/deepseek-v4-flash",
    "霓窝/gemini-3.8-flash"
  ],
  "request_max_retries": 3
}
```

备份：`cmd_config.json.bak-20261119-before-model-switch`。
重启后日志确认：`Selected openai_chat_completion(commandcode/deepseek/deepseek-v4.1-flash) as default chat model provider`。

> ⚠️ **deepseek 会输出很长的 reasoning**（实测 118~206 字），回复有 **~20 秒延迟**。
> 如果嫌慢，可以换回 `霓窝/gemini-3.8-flash` 或试试 `deepseek_default_source/deepseek-v4-flash`。

> ⚠️ `commandcode` 需要**带浏览器 UA**，否则 Cloudflare 返回 `403 error code: 1010`。AstrBot 内部应该没问题，但自己写脚本调它要注意。

### 11.2 队友掉线后重连的注意点

日志显示主机侧是 `Peer not connected`（`NetHostGameService.SendMessageToClientInternal`）。
这是主机在给已断开的 peer 发心跳，**不影响主机继续玩**，但队友重连大概率需要：

- **重启主机重建大厅**（最稳），或
- 用 mod 的「继续联机存档」（读档路径，见 DLL 里的 `multiplayer_load` 提示）

> 11-17 文档提过：握手失败会留下**幽灵玩家**，该 id 永久不能复用且战斗会卡住等它。
> 所以**队友掉线后最稳的做法是主机也重开**。
